# 三分鐘展示講稿

正式網址：<https://hackathon2026ctrlcity.pages.dev>

## 0:00–0:35｜問題

「調度人員不只要看見已經無車或無位，更需要提早知道下一個高風險站。我們把官方即時庫存與六個月歷史基線整合成 60 分鐘預判。」操作：指出資料時間、摘要與地圖。

## 0:35–1:25｜風險

「選行政區後，地圖與風險同步縮小範圍。點一站可比較現在、歷史基線與 60 分鐘推估；服務異常會獨立顯示，不會誤排進調度。」操作：切換篩選並開啟站點。

「優先分由風險、當下空滿、缺口與資料品質組成，是可解釋的排序，不是發生機率。」

## 1:25–2:30｜多站路線

「風險決定先後，庫存決定能搬多少，距離決定配對成本；條件相近時先把滿站的車直送缺車站，再以 12 台容量合併 2.5 公里內需求。」操作：展示一條路線的停靠順序、取放量與載量。

「距離是站點座標直線估算，不是道路導航；平台只提供分析與預測，不會確認案件或派遣車隊。」

## 2:30–3:00｜結論

「這套 Demo 已完成即時視覺化、60 分鐘預判、風險分流與多站物流規劃。正式比賽取得主辦方 AWS 帳號後，即可部署並啟用 AgentCore 解釋現有分析結果。」
