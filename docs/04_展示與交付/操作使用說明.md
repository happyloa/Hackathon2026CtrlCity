# 操作使用說明

這套 Demo 給調度值班人員使用；所有「確認／指派」都只保存在目前瀏覽器，不會通知機關或真實車隊。

## 一、即時調度

1. 開啟首頁，確認右上資料時間與「已對照站數」。系統每 5 分鐘檢查官方資料，也可按「立即更新」。
2. 用「行政區」縮小範圍；首頁數字依目前篩選同步更新。
3. 先看「調度工作佇列」：先覆核搬運任務，再確認其餘風險。
4. 展開「調度影響試算」，確認來源站與目的站調度後仍保有安全庫存，再按「指派」。
5. 點站名或地圖點位開啟站點面板；桌機從右側開啟，手機從底部開啟，可按 Esc／關閉鈕返回。

## 二、地圖判讀

| 顏色 | 意思 |
| --- | --- |
| 紅 | 目前無車，或 60 分鐘缺車風險；優先補車。 |
| 藍 | 目前無位，或 60 分鐘缺位風險；優先移車。 |
| 灰 | 官方未啟用或疑似服務異常；先人工確認。 |
| 橘 | 只有即時庫存、未匹配唯一歷史基線；不做未來預估。 |
| 綠 | 已匹配基線且暫無處理需求；只在「查看全市」模式顯示。 |

預設只顯示待處理站。可搜尋站名／行政區，直接從文字結果選站；「查看全市」用於空間確認，不代表全市站點都有風險。

## 三、站點、風險與任務頁

- 站點面板：比較現在、同站同時段歷史基線與 60 分鐘推估；滿位風險站另列 600m 內替代還車站。
- 全部風險：依「全部／待確認／已確認」篩選，點站名查看細節。
- 全部任務：查看完整來源、目的、距離、車數、優先分數與影響試算。
- 搬運來源與替代還車站只採用已對照歷史基線、服務正常且仍保有安全庫存的站點。
- 次頁上方的情境列會標示即時／歷史、行政區與資料時間；按「回工作台調整篩選」可保留情境返回。

## 四、歷史演練與證據

1. 首頁切到「歷史演練」並選回放時點；工作台統一以 60 分鐘判讀，避免不同區塊時間窗不一致。
2. 依同一套風險確認、站點檢視與任務指派流程操作。
3. 展開「判讀依據與交班摘要」查看保留測試與反事實調度試算。

歷史演練是可重現案例，不是即時資料；風險值是排序分數，不是事件發生機率。

## 五、異常與展示備援

- 官方資料失敗：畫面會保留上次成功資料並顯示錯誤；先按重新載入，仍失敗再切歷史演練。
- 歷史基線失敗：地圖會明示「僅顯示即時庫存」，按重新比對；不可把橘點稱為風險站。
- AWS AgentCore：正式環境啟用後才顯示「開始覆核」；只在按下時產生成本，失敗不影響既有預測與任務。

正式 AWS 部署所需資訊與指令見 [AWS 正式環境交接](../03_實作與驗證/AWS正式環境交接.md)。
