# 預測與資料方法

## 資料與預判

- 官方即時站況經唯讀 `/api/v1/live-stations` 取得；代理不保存資料。
- 主辦方六個月 CSV 只留本機且不進 Git；建置時轉為「站點 × 48 個半小時時槽」統計。
- 首頁只呈現即時模式；歷史資料只用於同站、同時段的 60 分鐘基線。
- 無法唯一匹配基線或服務異常的站點不產生未來庫存預估。

```text
官方即時庫存 + 同站 60 分鐘歷史基線
→ 缺車／缺位風險與安全庫存缺口
→ 告警排序、搬運建議與多站路線
```

## 告警優先分

```text
25 × 風險
+ 50 × 當下空滿
+ 20 × min(缺口 / 8, 1)
+ 5 × 資料品質
```

風險、當下空滿與資料品質皆以 0～1 表示，總分為 0～100。當下已空／滿至少 55 分，必定高於最高 50 分的純預測告警；55 分以上立即關注，30～54 分為高優先。這是可解釋的營運排序分，不是事件發生機率。服務異常獨立列示且不參與路線規劃。

## 多站路線

- 配對順序為：排除服務異常 → 依告警優先分排序 → 綜合缺口覆蓋率、相反庫存壓力與距離選擇來源／目的站。未來預測與一般供給站需有歷史基線；當下空／滿可依官方庫存直接互補。
- 在條件相近時，優先把滿站的車直接搬到缺車站；每筆建議最多 8 台，兩端都保留 15% 安全量。
- 每次更新評估前 80 筆可搬運高優先風險，最多產生 16 筆站間建議；所有風險仍完整顯示於告警中心。
- 車輛容量假設為 12 台；先以最高優先建議開一趟，再插入 2.5 公里內的相鄰需求。
- 每次插入都檢查載量、取放順序、來源站安全庫存與目的站安全空位。
- 距離採站點座標的 Haversine 直線估算，不是道路最佳化，也未使用真實車隊位置或班表。

## 限制

- 歷史評估採時間切分，避免未來資料洩漏；指標見[歷史風險基線評估](歷史風險基線評估.md)。
- 尚未納入天氣、活動、捷運班次、道路時間與真實調度紀錄。
- 平台只分析與預測，不確認案件、不建立工單、不派遣車隊。
