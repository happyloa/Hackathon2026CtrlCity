# 05: 示警區改為下拉,只收預測會缺車的站

> **先讀(冷啟動必要脈絡):**
>
> - `.scratch/dispatch-homepage-redesign/spec.md` —— 完整的問題陳述、決策依據與範圍界線
> - `CONTEXT.md` —— 領域詞彙。**「警示」的定義是關鍵:已經發生的缺車不算警示**,那是直接派車的對象。
>
> 示警區與建議派遣路徑(票 04)使用同一個門檻,差別只在時間點。若兩者收的站不一致,就是票 01 的統一沒做徹底。

**What to build:** 讓「示警」真的是預警,而不是重複已經知道的事。

首頁最上方一個示警下拉區,列出**未來 30 / 60 分鐘將缺車的站**。已經發生的缺車**不進示警區** —— 那些直接進建議派遣路徑,現在就該派車。已經發生的事不是預警。

示警區與建議派遣路徑使用**同一個近端缺車門檻**,差別只在時間點,不是兩套標準。所以不會出現「示警裡有這站,但路線裡沒有」。

清單以下拉方式呈現,方便瀏覽而不必捲動整頁;每一筆顯示站名、行政區、預估可借車數與建議補車台數;點一筆會定位到地圖上的位置。

**同時移除 KPI 卡列。** 「需注意站點」與示警區的數字是同一件事的兩種數法,並存只會製造疑惑(「到底 177 還是 116?」);「規劃路線數」在建議派遣路徑區塊本來就看得到;「空站/滿柱」計數併入示警區。

**Blocked by:** 01(示警收哪些站取決於統一後的缺車門檻)

**Status:** ready-for-agent

- [ ] 示警下拉區位於首頁最上方
- [ ] 示警區只列出預測會缺車的站(30 / 60 分鐘),不含目前已缺車的站
- [ ] 示警區顯示各視野的站數,以及空站與滿柱計數
- [ ] 每一筆顯示站名、行政區、預估可借車數、建議補車台數
- [ ] 建議補車台數為「補到安全庫存」,與建議派遣路徑一致
- [ ] 點選一筆會定位到地圖上該站的位置
- [ ] 示警區使用共用的安全庫存實作,不再自行內嵌計算
- [ ] KPI 卡列已移除,其中的空站/滿柱計數已併入示警區
