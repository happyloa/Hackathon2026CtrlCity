# 02: 地圖改為逐站柔邊疊加渲染

> **先讀(冷啟動必要脈絡):**
>
> - `.scratch/dispatch-homepage-redesign/spec.md` —— 完整的問題陳述、決策依據與範圍界線
> - `CONTEXT.md` —— 領域詞彙,特別是「鄰近群不是著色單位」這一條
> - `docs/02_研究與設計/map-library-selection.md` —— 為什麼不換地圖套件的一手查證
>
> **原型可以跑起來看。** 四種畫法的對照原型在 commit `6e52619`,該 commit 已被本票移除,但可用 `git show 6e52619` 或簽出該版本實際操作,對照下方參數理解為什麼選定這一種。

**What to build:** 讓調度人員在地圖上看出「哪一帶在燒」,而不只是「哪一站在燒」。

現在的地圖畫的是一顆顆獨立的站點圓點與公尺半徑的圓圈,看不出區域趨勢。改成逐站畫柔邊色斑並以半透明疊加,重疊處自然融合,形成「一片綠底、有問題的地方透出紅色」的效果。

**鄰近群不是著色單位。** 著色逐站進行,視覺上的「一塊」是疊加浮現出來的,不是先算好的形狀。

**綠色只在底層畫一次**,這是整個渲染的關鍵:若讓每個健康站各自疊一層綠,站點密集的地區會因為站多而顯得更嚴重,與事實相反。

以下參數由拋棄式原型以 1,526 站真實資料對照四種畫法後選定,它們比文字描述更精確:

```text
半徑        500 公尺,依當前緯度與縮放層級換算為像素(非固定像素)
合成模式     source-over  ← 不是 lighter
底層        所有營運中站點,綠 rgb(34,197,94),peak alpha 0.10,只畫一次
上層        依序疊加,後畫者覆蓋先畫者:
              灰   0.22
              黃   0.20
              天青藍 0.36
              橘   0.36
              紅   0.36   ← 最後畫,永遠在最上面
漸層停點     0 → peak / 0.55 → peak×0.5 / 1 → 0
服務異常     不進底層(它不提供服務),只在上層以灰色出現
```

被排除的三種畫法與原因:**強度堆疊**(熱力圖套件的標準做法)畫的是站點密度而非缺車嚴重度,方向與需求相反;**全疊加**的綠色會互相疊深;**兩層**只表達紅與橘,黃色與滿柱無法呈現。

**不更換地圖套件。** 地圖套件僅負責底圖與座標轉換,疊層自繪。原本考慮更換的三個理由(深色底圖、內建熱力圖層、明暗切換)在「地圖恆為淺色」與「自繪疊層」兩項決定之後都不再成立。

**Blocked by:** 01(需要嚴重度分級決定每站的顏色)

**Status:** ready-for-agent

- [ ] 首頁地圖以自繪疊層呈現,不再使用地圖套件內建的圓點標記畫風險圓圈
- [ ] 綠色底層對所有營運中站點只畫一次,站點密集不會使底色疊深
- [ ] 上層依嚴重度由淺到深疊加,紅色永遠在最上面不被覆蓋
- [ ] 半徑為地理上的 500 公尺,縮放時色斑大小隨之改變
- [ ] 服務異常站不出現在綠色底層
- [ ] 疊層在平移與縮放時跟隨地圖,不錯位
- [ ] 淺色底圖上街道與地名仍可辨識,未被色斑完全遮蔽
