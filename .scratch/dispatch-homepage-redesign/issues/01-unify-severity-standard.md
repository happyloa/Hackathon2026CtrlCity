**What to build:** 讓地圖、示警清單、建議派遣路徑三處對同一個站說同一句話。

現在同一個站在三個地方會被說成三種嚴重度:示警清單依模型風險分數說它最嚴重、派遣路徑依營運優先分數把它排在後面、而兩邊用的安全庫存比例還不一樣(示警 10%、派遣 15%),所以會出現「示警說這站要補,但路線裡找不到它」。維修中的站點更是被標成最紅的一筆,但派車過去根本無法處置。

改成:嚴重度一律以**可借車數**判定,不再使用模型算出的風險等級;安全庫存只有一份實作;服務異常成為獨立狀態而非「最嚴重的風險」。

判定順序即優先序,六個級別互斥:

| 級別 | 條件 | 顏色 |
|---|---|---|
| 服務異常 | 站點非營運中 | 灰 |
| 滿柱 | 可還車位 = 0 | 天青藍 |
| 完全缺車 | 可借車數 = 0 | 紅 |
| 近端缺車 | 可借車數 < 3 | 橘 |
| 偏低 | 可借車數 < 總車格一半 | 黃 |
| 正常 | 其餘 | 綠 |

**門檻與數量刻意分開,不是疏漏。** 判斷「何時該補」用近端缺車(可借車數低於 3 台);計算「該補多少」用安全庫存,補到總車格的 15%(下限 3 台),因為一個 60 格的大站補 3 台等於沒補。
